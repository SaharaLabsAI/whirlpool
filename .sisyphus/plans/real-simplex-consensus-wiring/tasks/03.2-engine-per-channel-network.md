## Context
`CommonwareEngine<A, S, N, C>` currently constrains `N: p2p::NetworkProvider` which exposes a single `start() -> (Sender, Receiver)`. The real simplex engine requires 3 channel pairs (vote, certificate, resolver) obtained from `CommonwareNetworkProvider::start_per_channel() -> PerChannelNetwork`.

This sub-task changes the engine's network type parameter to accept the per-channel provider, updates the constructor, and fixes all test call sites.

Additionally, the context type `C` currently has bounds `Rng + Spawner + Metrics + Clock` but the vendor `simplex::Engine` requires `Clock + CryptoRngCore + Spawner + Storage + Metrics`. This task adds the missing bounds (`Storage`, and replaces `Rng` with `CryptoRngCore` if needed).

## What to do
1. **Update `CommonwareEngine` struct type parameter** `N`:
   - Change from `N: p2p::NetworkProvider` to accept `CommonwareNetworkProvider` (from `crates/p2p-commonware/src/provider.rs`).
   - This may mean: changing the trait bound, replacing the generic with a concrete type, or introducing a new `PerChannelNetworkProvider` trait.
2. **Update context bounds** on `C`:
   - Add `Storage` bound if missing.
   - Ensure `CryptoRngCore` is present (vendor requires it on the Engine context).
3. **Update `CommonwareEngine::new()` constructor** signature to accept the new network type.
4. **Update all test call sites** in `engine.rs` and `tests.rs`:
   - `MockNetworkProvider` must be replaced or adapted to satisfy the new per-channel interface.
   - Tests that call `CommonwareEngine::new(...)` need updated arguments.
5. **Verify** the workspace builds (tests may still fail — that's expected until 03.3 wires the real engine).
