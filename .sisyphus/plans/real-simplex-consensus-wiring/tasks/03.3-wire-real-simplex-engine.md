## Context
Replace the stubbed `CommonwareEngine::start()` body with real vendor `simplex::Engine` wiring. The current implementation (engine.rs ~lines 88-164) spawns a `std::thread` that simulates finalization every 5 seconds by incrementing an `AtomicU64`. It never calls `simplex::Engine::new(...)` or `.start(...)`.

After Task 03.2, the engine accepts a per-channel network provider. This task wires the actual vendor engine startup per FLOWS.md Flow 1.

## What to do
1. **Remove** the stub simulation thread entirely from `start()`.
2. **Wire real engine startup** following FLOWS.md Flow 1:
   a. Call `network.start_per_channel()` → `PerChannelNetwork { vote, cert, resolver, network_handle }`.
   b. Create `mpsc::channel(config.mailbox_size)` → `(tx, rx)`.
   c. Create `Mailbox::new(tx)` (implements `Automaton + Relay`).
   d. Spawn `MailboxActor::new(rx, height.clone(), app.clone())` as an async task via the context.
    e. Create `FinalizationSink::new(height.clone())` — this is the `EventSink` impl needed by `AppAdapter`.
    f. Create `AppAdapter::new(app.clone(), sink)` where `sink` is the `FinalizationSink` (or the engine's Arc<S> sink field). `AppAdapter` implements `Reporter`.
   g. Build `simplex::Config` with:
      - `scheme`: ed25519 signer from `config.signer()`
      - `elector`: `RoundRobinElector` (from vendor simplex)
       - `blocker`: Oracle obtained from `network_handle` (the `PerChannelNetwork.network_handle` — call `.control(pk)` or equivalent to get an Oracle/Blocker instance, matching vendor test patterns in `simplex/mod.rs`)
      - `automaton`: the `Mailbox` instance
      - `relay`: the same `Mailbox` instance (it's Clone)
      - `reporter`: the `AppAdapter`
      - `strategy`: `Sequential` (from vendor simplex)
      - `partition`, `mailbox_size`, timing params: from `CommonwareConfig`
      - `buffer_pool`: `PoolRef::new()`
   h. `simplex::Engine::new(context, simplex_config).start(vote_channels, cert_channels, resolver_channels)` → `Handle<()>`.
   i. Wrap in `RunningEngine` with: shutdown = abort the handle, height = shared `AtomicU64`, running = `AtomicBool`.
3. **Update `RunningEngine`** stop/shutdown logic to abort the vendor handle instead of the stub thread.
4. **Handle errors**: network startup failure → `ConsensusError::Other`. Call `simplex_config.assert()` before `Engine::new()` — this panics on invalid config, which is acceptable for a programming error (misconfigured fields). Do NOT wrap `assert()` in error handling — a panic here indicates a bug in our wiring, not a runtime error.
