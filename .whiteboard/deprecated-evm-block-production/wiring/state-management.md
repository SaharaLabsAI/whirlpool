## Blockers
- **INV-01 (Execution Visibility)**: BLOCKER. Current default provider is `NoopTxSource`, so state wiring never receives non-empty tx effects in runtime happy path (`crates/whirlpool-node/src/main.rs::main`, `docs/design/evm-block-production/.design-scratch/run-20260301-1330/domains-wiring-context.md`).
- **INV-02 (Verification Integrity)**: BLOCKER. Wiring reaches `verify`, but behavior only compares current `state_root`; no grounded evidence of recomputing tx/receipt/gas artifacts (`docs/design/evm-block-production/.design-scratch/run-20260301-1330/domains-wiring-context.md`).
- **INV-03 (Verification Read-Only)**: PARTIAL/GROUNDED for current path (read lock + `state_root` check), but future full re-execution safeguards are UNKNOWN.
- **INV-04 (Snapshot Safety)**: UNKNOWN/BLOCKER. `Clone` + `commit` exist in state crate, yet no explicit runtime snapshot/rollback orchestration seam is wired.
- **INV-05 (Commit Atomicity)**: BLOCKER. Domain has `commit`, but finalize-to-commit bridge is not visible in in-scope consensus app interface and node wiring.
- **INV-06 (Root Consistency)**: BLOCKER for non-empty blocks; current proposal path emits empty execution artifacts, so roots are not derived from actual tx execution in runtime intent path.
- **INV-07 (Proposal Determinism)**: Trivially satisfied for empty-block proposal path; UNKNOWN for real tx execution because ordering/selection policy interfaces are not grounded in current wiring.
