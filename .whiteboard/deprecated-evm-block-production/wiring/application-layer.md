## Blockers
- BLOCKER (INV-01): Default tx source in this domain is `NoopTxSource`, so non-empty execution visibility cannot be satisfied without replacing provider wiring (`crates/app/src/traits.rs::NoopTxSource::pending`).
- BLOCKER/PARTIAL (INV-02): Adapter interface maps verification to pass/fail (`Result<(), ConsensusError>`) and proposal to `Option<Block>`, which drops execution-detail/error richness at consensus boundary (`crates/app/src/adapter.rs::ApplicationAdapter::{propose,verify}`).
- UNKNOWN (INV-03): Read-only verification guarantee is not encoded in trait signatures; depends on concrete `Application::verify` implementation behavior (`crates/app/src/traits.rs::Application`).
- UNKNOWN/BLOCKER candidate (INV-04): No snapshot/rollback contract in Application Layer traits/adapter; safety depends on lower-layer implementation and orchestration not defined here.
- BLOCKER (INV-05): No finalize/commit callback in Application Layer bridge contracts (`Application` + consumed `ConsensusApp`), so commit atomicity wiring is outside exposed interface path (`crates/app/src/traits.rs::Application`, `crates/consensus/src/app.rs::ConsensusApp`).
- UNKNOWN/BLOCKER (INV-06): `EvmBlock`/`ExecutionResult` carry roots and gas fields, but this wiring layer cannot prove they derive from actual execution without concrete app evidence.
- UNKNOWN (INV-07): Deterministic tx ordering/policy is unspecified in `TxSource::pending()` contract, so deterministic proposal under non-empty input is not guaranteed at interface level.
